# ADR 0000: 重要な意思決定をADRで記録する

- Status: Accepted
- Date: 2026-11-16

## Context

技術試験では、実装したコードだけでなく、判断理由と代替案の検討有無を説明できる必要がある。30時間という制約の中で判断を後から再構成すると、理由やトレードオフが失われやすい。

## Decision

設計、技術、外部サービス、開発プロセスに関する重要な意思決定を `docs/adr/` 配下のADRとして記録する。

ADRには少なくとも、状況、判断基準、決定、比較した選択肢、結果を記載する。未決定事項は `Proposed` とし、合意後に `Accepted` へ変更する。

## Consequences

### Positive

- 面談時に判断理由と代替案を説明できる。
- 後続の判断で前提を確認できる。
- READMEを詳細な検討記録で肥大化させずに済む。

### Negative

- 意思決定のたびに短い記録コストが発生する。
- 実装とADRの同期を維持する必要がある。
