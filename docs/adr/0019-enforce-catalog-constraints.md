# ADR 0019 弁当と日別献立のタイプをDBで一致させる

- Status: Accepted
- Date: 2026-11-23
- Linear: LET-16、LET-29

提供日ごとに同じタイプの弁当は1件まで登録できる。管理者が弁当のタイプを編集しても、すでに組んだ献立でこの条件を保つ必要がある。

Railsのモデルは登録・編集の前に入力を検証し、利用者に返すエラーを持つ。弁当タイプ、非負の価格と上限、郵便番号の形式はDBのCHECK制約でも確認する。必須項目にはNOT NULL、重複を許さない組み合わせには一意インデックスを置く。

日別献立の弁当タイプを弁当から写し、日別献立の「弁当ID・タイプ」を弁当の「ID・タイプ」へ複合外部キーで結ぶ。同じ提供日・タイプには一意インデックスを置く。弁当のタイプ変更はDBが日別献立に反映し、変更後にいずれかの日で重複が生じる更新は拒む。献立を同時に登録しても一意制約が働く。

モデルから関連する弁当を検索して重複を調べる方法も検討した。この方法では同時登録を防ぐために、登録とタイプ変更のすべての経路が同じロック手順を守る必要がある。複合外部キーを採用した分、日別献立にタイプの列と弁当に参照用の一意インデックスが増える。

今回追加する3テーブルは課題で指定された弁当、配達エリア、日別献立に対応する。残数は注文に応じて変わるため保存しない。今後、課題指定以外のテーブルを追加するときは用途と理由をREADMEに記録する。
