# ADR 0019 弁当タイプを弁当に持たせ、提供日ごとの重複をRailsで防ぐ

- Status: Accepted
- Date: 2026-11-23
- Linear: LET-16、LET-29

管理者が弁当のタイプを変更すると、登録済みの献立にも新しいタイプが反映される。タイプは `bentos.bento_type` に保存し、献立から弁当を参照する。提供日ごとに同じタイプの弁当は1件まで登録できる。

Railsは献立の登録、提供日・弁当の差し替え、弁当タイプの変更を検証する。どの操作でも同じ献立テーブルのロックを取得し、PostgreSQLの既定の分離レベル（READ COMMITTED）で先行する変更の確定後に重複を調べる。ロックは保存トランザクションの終了時に解放される。まだ献立の行がない日も保護でき、通常の閲覧は並行できる。管理者による書き込みは提供日が異なっても順番に処理される。

DBは弁当への外部キー、提供日と弁当IDの一意制約、必須列、タイプの選択肢、価格・提供数上限の下限、郵便番号の形式と一意性を保証する。同日同タイプの検証はモデルの保存経路にあるため、今後一括登録を設ける際もこの経路を使う。直接SQLや `insert_all!` による書き込みまで対応する案では、両テーブルへのトリガーと同時更新対策の保守が必要になるため、今回は採用を見送った。

今回の3テーブルは課題指定の弁当、配達エリア、日別献立に対応する。残数は注文から計算する。
