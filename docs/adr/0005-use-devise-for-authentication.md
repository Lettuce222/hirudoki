# ADR 0005: 利用者と管理者の認証にDeviseを採用する

- Status: Accepted
- Date: 2026-11-16

## Context

課題では利用者と管理者の両方にログインが必要である。利用者は画面から登録できるが、管理者は登録画面を持たず、シードデータで用意する。指定されたデータベース設計に従い、利用者と管理者は別のモデルとして扱う。

30時間の制約内で、パスワードの安全な保存、セッション管理、ログイン失敗時の処理を堅牢に実装する必要がある。

## Decision

利用者モデルと管理者モデルの認証にDeviseを採用する。

- 利用者には登録、ログイン、ログアウトを提供する。
- 管理者にはログイン、ログアウトだけを提供する。
- 管理者アカウントはシードデータから作成する。
- 利用者向け画面と管理者向け画面のルーティングおよび認証境界を分離する。
- 認証とは別に、各操作の認可をsystem specとrequest specまたは同等の境界テストで保証する。

## Alternatives Considered

### Rails標準のAuthentication Generator

依存を増やさず実装を所有できる利点がある。一方、利用者と管理者の2種類の認証、利用者登録、パスワード回りの画面を今回の制限時間で整える作業が増えるため不採用とした。

### 独自認証

要件に合わせて最小構成にできるが、セッションやパスワード処理で不具合・脆弱性を作る危険があり、課題の評価対象に対して時間を使う場所として適切でないため不採用とした。

### 利用者と管理者を単一モデルのroleで分ける

認証構成は単純になるが、課題で与えられた利用者・管理者のテーブル設計と役割を変えることになるため不採用とした。

## Consequences

### Positive

- 認証の定型処理を短時間で堅牢に構築できる。
- 利用者と管理者のセッション境界を明確にできる。
- 認証の実装量を減らし、業務ルールのTDDに時間を配分できる。

### Negative

- Deviseの設定、ルーティング、コントローラー拡張を理解する必要がある。
- 2つのDeviseモデルによるルートやヘルパーの混同を防ぐ必要がある。
- 認証ライブラリだけでは操作単位の認可を保証できないため、別途認可設計が必要になる。
